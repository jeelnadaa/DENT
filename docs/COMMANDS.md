### `/dent`

The main entry point: understand any design, front-end or media request, pick the right sub-commands, chain them and deliver the best result.

- **Usage:** `/dent <anything you want designed, built, fixed, reviewed or produced>`
- **Default depth:** decided by the router
- **Loads:** references/workflow/orchestration.md; SKILL.md §1.0 and §3
- **Does:** Fill the signal card from orchestration → Map the signals to a main command + companions with the table in Step 2 → Expand into the default pipeline for each deliverable (Step 3) and tell the user the plan in one line → Ask only the questions the pipeline needs, one at a time, effort first (Step 4) → Run each sub-command's file (`commands/<name> → If the effort is All-out, also run `references/workflow/all-out → Finish with one close-out
- **Delivers:** Whatever the pipeline produces, plus the gate results, scorecard(s), attribution and a one-line next step.
- **Definition:** [`skills/dent/commands/dent.md`](../skills/dent/commands/dent.md)

### `/dent:plan`

Inspect the context and produce an audited PLAN.md without building anything.

- **Usage:** `/dent:plan <goal or feature>`
- **Default depth:** Advanced (or Critical if risky)
- **Loads:** references/workflow/planning-and-plan-audit.md; templates/PLAN.md; references/modes-existing-products.md; references/creative-direction.md
- **Does:** Gather Confirmed / Assumed / Unknown facts; inspect the repository if there is one → Ask only about Unknowns that change correctness, risk or direction (one question at a time) → Fill templates/PLAN → Audit the plan (planning file §4) → Present a short summary
- **Delivers:** PLAN.md (written to the project, or printed) + plan-audit table + open questions. No implementation.
- **Definition:** [`skills/dent/commands/plan.md`](../skills/dent/commands/plan.md)

- **Delivers:** Working files, Decision Log, gate results, scorecard, attribution; DESIGN.md after approval.

### `/dent:redesign`

Redesign an existing product while preserving the behaviour users rely on.

- **Usage:** `/dent:redesign <product or screens>`
- **Default depth:** Advanced
- **Loads:** references/modes-existing-products.md §3; references/workflow/execution-and-scope.md; references/workflow/planning-and-plan-audit.md; references/workflow/verification.md §8
- **Does:** Inventory screens, flows, components and drift; screenshot the current version as a baseline → List what must stay (navigation, terminology, key positions, features) and ask what is sacred → Plan the redesign + migration (incremental by default) and audit it → Build in phases; never drop a feature because it wasn't in the screenshot you were given → Compare before/after per screen; classify every difference
- **Delivers:** Before/after comparison with reasons, migration plan, updated DESIGN.md, regression results.
- **Definition:** [`skills/dent/commands/redesign.md`](../skills/dent/commands/redesign.md)

### `/dent:extend`

Add a feature or screen that fits the existing product and design system.

- **Usage:** `/dent:extend <feature>`
- **Default depth:** Standard
- **Loads:** DESIGN.md; references/workflow/execution-and-scope.md §1–2; references/modes-existing-products.md §2
- **Does:** Read DESIGN → Find the integration points and the screens that share components → Build the feature with existing tokens/components; add new ones only in the existing convention → Verify the new feature and the neighbouring screens; update DESIGN
- **Delivers:** The feature, verification results, DESIGN.md changelog line.
- **Definition:** [`skills/dent/commands/extend.md`](../skills/dent/commands/extend.md)

### `/dent:implement`

Implement an approved PLAN.md or DESIGN.md accurately.

- **Usage:** `/dent:implement <path to PLAN.md or DESIGN.md>`
- **Default depth:** As in the plan
- **Loads:** the plan/spec itself; references/design-tokens-and-code.md Part 2; references/workflow/execution-and-scope.md; references/workflow/verification.md
- **Does:** Read the plan/spec fully → If anything material changed, update the plan and re-audit before building → Implement phase by phase; tokens first; update the traceability matrix as you go → Verify every requirement against its acceptance criterion; record deviations
- **Delivers:** Implementation + traceability matrix with statuses + verification report.
- **Definition:** [`skills/dent/commands/implement.md`](../skills/dent/commands/implement.md)

### `/dent:fix`

Diagnose and fix one specific UI/UX problem with the smallest correct change.

- **Usage:** `/dent:fix <the problem>`
- **Default depth:** Quick (Critical if risky area)
- **Loads:** references/workflow/verification.md; references/foundations-and-components.md
- **Does:** Reproduce or precisely understand the problem (screenshot, steps, viewport) → Find the root cause, not the symptom → Make the smallest correct fix using existing tokens/components → Verify the fix and nearby regressions (other screens using the same component)
- **Delivers:** Cause, fix, before/after evidence, what else was checked.
- **Definition:** [`skills/dent/commands/fix.md`](../skills/dent/commands/fix.md)
